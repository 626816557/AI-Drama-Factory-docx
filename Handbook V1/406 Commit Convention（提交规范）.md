# 一、本文档回答什么问题？

本文档回答：

> **AI Drama Factory 应如何编写 Git Commit Message？**

Commit Convention 定义整个项目的提交规范。

Commit Message 是项目历史的重要组成部分。

它不仅记录代码。

更记录：

设计。

决策。

演进。

---

# 二、设计目标（Purpose）

优秀 Commit 应满足：

- 易理解
- 易检索
- 易 Review
- 易追溯
- 易回滚

任何 Commit。

都应能够独立说明：

为什么修改。

修改了什么。

影响哪些内容。

---

# 三、核心原则（Core Principles）

Factory 坚持：

## One Commit One Purpose

一次 Commit。

只完成一个目标。

例如：

新增：

Project Repository。

修复：

Image Timeout。

不要：

一次 Commit 完成多个功能。

---

## Commit Explains Why

Commit Message 应说明：

为什么修改。

而不仅仅是：

修改了什么。

---

## Commit Is History

Commit Message 是：

项目历史。

不是聊天记录。

未来任何人。

都应能够根据 Commit 理解项目演进。

---

## Keep It Clear

保持：

简洁。

准确。

一致。

避免：

无意义描述。

---

# 四、推荐格式（Commit Format）

推荐格式：

```
type(scope): summary
```

例如：

```
feat(project): add project lifecycle manager

fix(renderer): resolve image timeout issue

docs(handbook): complete architecture chapter

refactor(core): simplify event dispatcher

test(api): add project service tests
```

---

# 五、Commit Type

Factory 推荐使用：

```
feat

fix

docs

refactor

test

perf

build

ci

style

chore
```

各类型职责明确。

保持统一。

---

# 六、Summary 编写原则

Summary 应满足：

- 使用英文
- 简洁明确
- 不超过一行
- 描述最终结果

例如：

```
add story validation engine

support project versioning

improve asset storage
```

避免：

```
update

modify

change

fix bug

```

过于模糊。

---

# 七、禁止行为

禁止：

```
update

test

123

修改一下

final-final

再次修改
```

禁止：

复制 Commit。

禁止：

一次 Commit 包含多个无关功能。

---

# 八、Commit 粒度（Commit Size）

推荐：

每个 Commit：

完成一个独立目标。

例如：

```
Project CRUD

Renderer Retry

Dashboard Layout
```

而不是：

```
完成整个 Dashboard

完成整个 Backend
```

Commit 越小。

越容易：

Review。

定位。

回滚。

---

# 九、Review 原则

Review Commit 时。

应检查：

✓ 是否完成单一目标？

✓ Message 是否表达清楚？

✓ 是否容易回滚？

✓ 是否符合 Handbook？

不符合。

应重新提交。

---

# 十、AI Commit

未来。

AI 自动生成代码时。

Commit Message 仍应遵循本规范。

AI 不得生成：

```
Generated by AI
```

作为 Commit Message。

Commit 应体现：

真正完成的工作。

而不是生成方式。
